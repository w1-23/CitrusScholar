# Independent corpus host integration

`CITRUS_CORPUS_MODE=isolated` skips registration of the legacy Web corpus maintenance middleware and worker. The default remains `legacy`. `CITRUS_CORPUS_FETCH_GROWTH=1` enables backend-only acquisition for the dedicated single-paper Fetch operation. It does not add a chat write tool or a normal-user intake endpoint. Routine Web search and generic page Fetch are read-only.

The host hands off public paper identifiers off the request thread. A fixed bibliographic authority confirms publication type and matches those identifiers. Unknown or restricted rights keep only a bibliographic record and public link. Full text is accepted automatically only from a verified version-pinned source with a supported open license and byte-level evidence. A discovery result, generated snippet, title alone, or model-provided permission never authorizes shared text. Automatic registration cannot regrant a revoked exact version. Inbox, original, prepared, granted and published remain distinct states.

`CITRUS_CORPUS_READ=1` and `CITRUS_ISOLATED_CORPUS_ROOT` enable sixth-corpus reads. `CITRUS_ISOLATED_CORPUS_EMBEDDING_CACHE` points to the offline CPU model cache used by the published generation. Normal local-RAG policy still applies. The independent publisher validates a candidate before atomically replacing `active_index.json`. Without `read_generation`, each search pins the current generation, so publication requires no Web restart. Existing citation references keep their exact generation and current rights check. Replacing the Web/Worker release only changes the background intake policy and implementation. Do not overwrite corpus data during a source rollback.

Administrators can submit one DOI, URL, or pre-staged inbox path at `POST /api/v2/isolated-corpus/admin/intake` and retrieve its durable status at `GET /api/v2/isolated-corpus/admin/intake/{job_id}`. An inbox path requires its expected raw SHA-256. A DOI or URL requires live host Fetch authorization at admission plus a network-enabled standalone worker at dispatch. Use an operator-controlled `--network-marker` if the worker should respond to an external revocation file. The worker stays external to Web and chat lifecycle. The `agent_literature` family uses the existing search tool and citation UI. The five materialized corpora remain in their existing registry and generation. Legacy citation links continue to check their existing catalog and rights through a read-only path.

To exercise the copy check in a temporary fixture, run `python -m src.corpus_integration.migration --legacy-root /path/to/old/shared --base-file FILE` with five separate `--base-file` arguments. It uses SQLite backup to an in-memory snapshot, verifies bounded sample Markdown hashes and checks the active pointer and five file fingerprints before and after. It is a dry run. Activation and rollback are standalone commands documented by the corpus package.

Set `CITRUS_CORPUS_READ_GENERATION` to pin an experiment deployment to one isolated generation. A missing or invalid pinned generation leaves that corpus unavailable. Current rights and the local-RAG switch still apply to every read. Historical links continue to resolve their own exact generation.

For Apptainer deployments, use the existing launcher with an `isolated_corpus` JSON object containing `root`, `read`, `growth` and, when reading, `embedding_cache`. `read_generation` is optional. Remove `shared_literature_single_web` when enabling this object. Web mounts the dedicated corpus root and read-only encoder cache. The existing offline Code Worker does not receive these mounts. Run the corpus CLI worker and publisher separately.
