# Independent corpus host integration

`CITRUS_CORPUS_MODE=isolated` skips legacy Web corpus maintenance. The default remains `legacy`. Backend-only growth requires both `CITRUS_CORPUS_FETCH_GROWTH=1` and `CITRUS_CORPUS_DURABLE_INTAKE=1`. Routine Web search, generic page Fetch, private query titles, and user uploads do not feed this queue.

Both intake paths return a durable receipt from the existing SQLite queue. The foreground path preserves the already fetched, version-pinned official PMC Cloud text bytes and checks the source metadata's content checksum and local SHA-256. The independent consumer corroborates exact journal identity and title without requesting the original again. The background path resolves a DOI, PMID, PMCID, or explicitly public title. Title matching uses a bounded exact, unique authority result. Only the returned record title is cataloged. If the origin or publication rights cannot be proved, the result remains bibliographic only. Independently resolved editions may reuse a previous original only when it matches the checksummed official object and version-specific reuse evidence. Provider HTML, JATS or PDFs, snippets, and generated text are not automatic originals without an equivalent trusted byte-level and version-bound rights contract. An operator can stage genuine HTML, JATS or PDF into the specific corpus inbox, submit the exact expected SHA-256, and independently grant that specific prepared version with the existing `rights granted` command. An embedded license label alone does not grant it.

Roll out the standalone intake worker from the same source as Web first. Keep the new Web producer switch disabled until the worker is configured with the same absolute corpus root, `CITRUS_CORPUS_MODE=isolated`, `CITRUS_CORPUS_FETCH_GROWTH=1`, `CITRUS_CORPUS_DURABLE_INTAKE=1`, and the existing live capability policy/revocation configuration. Give the worker access to the same account store via `CITRUSQA_PROJECT_ROOT` and mount the initialized account state read-only. Its SQLite account connection is read-only and admits only an active, approved principal in the same account epoch (and current admin for admin submissions). A disable/re-enable invalidates older receipts. Use `PYTHONPATH` including both `packages` and `01_src`, then run the existing `python -m citrus_corpus --root ROOT worker --watch --allow-network --allow-automatic --network-marker /absolute/worker-network-enabled`. The marker is optional and should be operator-controlled when used. Existing non-automatic intake and the publisher require no new flags. Older workers cannot claim protected automatic rows, so disable producers before rollback and leave pending receipts for a compatible worker. No active generation is modified by this configuration alone.

`CITRUS_CORPUS_READ=1` and `CITRUS_ISOLATED_CORPUS_ROOT` enable sixth-corpus reads. `CITRUS_ISOLATED_CORPUS_EMBEDDING_CACHE` points to the offline CPU model cache used by the published generation. Normal local-RAG policy still applies. The independent publisher validates a candidate before atomically replacing `active_index.json`. Without `read_generation`, each search pins the current generation, so publication requires no Web restart. Existing citation references keep their exact generation and current rights check. Replacing the Web/Worker release only changes the background intake policy and implementation. Do not overwrite corpus data during a source rollback.

Administrators can submit one manually reviewed DOI, URL, or pre-staged inbox path at `POST /api/v2/isolated-corpus/admin/intake` and retrieve its durable status at `GET /api/v2/isolated-corpus/admin/intake/{job_id}`. The separate `POST /api/v2/isolated-corpus/admin/public-paper` accepts one public identifier or attested public title for automatic background acquisition. The admin console and `GET /api/v2/isolated-corpus/admin/intake` report recent receipt, preparation, current rights, and publication state without exposing source text or account identity. An inbox path requires its expected raw SHA-256. A DOI or URL requires live host Fetch authorization at admission plus a network-enabled standalone worker at dispatch. Use an operator-controlled `--network-marker` if the worker should respond to an external revocation file. The worker stays external to Web and chat lifecycle. The `agent_literature` family uses the existing search tool and citation UI. The five materialized corpora remain in their existing registry and generation. Legacy citation links continue to check their existing catalog and rights through a read-only path.

To exercise the copy check in a temporary fixture, run `python -m src.corpus_integration.migration --legacy-root /path/to/old/shared --base-file FILE` with five separate `--base-file` arguments. It uses SQLite backup to an in-memory snapshot, verifies bounded sample Markdown hashes and checks the active pointer and five file fingerprints before and after. It is a dry run. Activation and rollback are standalone commands documented by the corpus package.

Set `CITRUS_CORPUS_READ_GENERATION` to pin an experiment deployment to one isolated generation. A missing or invalid pinned generation leaves that corpus unavailable. Current rights and the local-RAG switch still apply to every read. Historical links continue to resolve their own exact generation.

For Apptainer deployments, use the existing launcher with an `isolated_corpus` JSON object containing `root`, `read`, `growth` and, when reading, `embedding_cache`. `read_generation` and `durable_intake` are optional. Set `durable_intake` to the JSON boolean `true` only after the independent consumer is ready. Remove `shared_literature_single_web` when enabling this object. Web mounts the dedicated corpus root and read-only encoder cache. The existing offline Code Worker does not receive these mounts. Run the corpus CLI worker and publisher separately.
