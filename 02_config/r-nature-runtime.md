# Pinned offline Nature Figure R runtime

The Nature tool supports a genuine R backend for `marginal`, the two-variable scatter with top and right marginal count histograms, stacked by group when one is mapped. Map the two numeric columns and optionally one categorical group column in an authorized UTF-8 CSV. Up to 12 explicit groups are supported. The same observations feed every panel. By default an invalid numeric or empty mapped group value fails the job. Only `drop_incomplete=true` permits exclusion and the returned count reconciles every record. No tests or summary inferences are computed. The other four pinned CLI templates still use Python when Python was requested.

CitrusScholar maintains the fixed `nature_skill_marginal.R` adapter. The active upstream Nature skill is commit `c6701dbea29afa7c596d029b957b7edc92130ea5`. That commit supplies an R alignment helper and backend-neutral audit tools, but its executable plotting templates are Python only. The worker snapshot contains the app's fixed R adapter, a transport script, and the exact approved upstream auditing bytes. It cannot evaluate supplied R programs or accept supplied command or output paths. Separately authorized generic Code is unchanged, with its existing offline policy, and could call binaries present in the selected sandbox installed by the operator. This integration enables no new generic endpoint.

The deliverables are the unmodified `svglite` SVG, the exact audited one-page Cairo PDF and LZW TIFF at 600 dpi. The worker checks measured physical panel rectangles, the 5 pt PDF text floor and collisions. The QA receipt preserves upstream's raw alignment capture and raw collision verdict. The pinned R upstream helper's `null`-unit conversion can collapse panels, so the candidate measures actual viewports on the final Cairo device while retaining upstream's panel/grid metadata. The pinned PDF audit can join separated labels batched in one Cairo trace. The candidate uses raw text glyph-line boxes from the same PDF and runs the unchanged upstream geometry rules on them, alongside its original clipping, stroke, fill and image evidence. No audit passes are inferred from successful rendering. Visual/scientific review is not automated. The Workbench derivative is separate and registered only when its existing strict SVG validator accepts the original. An unsupported SVG can still be downloaded unchanged.

## Offline reproduction

Run the Linux x86-64 build tool with Python 3.11 or later and the existing local Apptainer host. Supply a verified copy of the unchanged base SIF, the exact micromamba executable, and the package archive closure listed in `r-nature-runtime.lock.json`. The URLs are provenance only during this build. Populate the input store beforehand, then supply either a flat archive directory or the matching micromamba package cache. Do not use a live conda environment as an input. Every archive is copied to private build staging and checked against its locked size and SHA-256. Installation uses an explicit local `file://` package set and micromamba offline mode. The resulting read-only prefix is `/opt/citrus-r`, with no runtime data bind, host fallback, downloads, package installation, or network permissions.

```sh
python3 02_config/r-nature-image.py \
  --base /trusted/sandbox-fusion.sif \
  --micromamba /offline/micromamba \
  --packages /offline/pkgs \
  --output /trusted/new-sandbox-nature-r.sif
```

The build checks inherited Python dependencies and exact R 4.4.3, ggplot2 4.0.4, patchwork 1.3.2, svglite 2.2.2, ragg 1.5.2, jsonlite 2.0.0 and Cairo. The closure contains 136 archives, including the experimental `ComplexHeatmap` package and its dependencies. Their presence does not advertise additional executable Nature templates. The immutable **candidate** derivative digest is `f576f83f98f6c18c972babb866e0065ca5d694cb6c9b5fe47dacd4b78dda8f62`. SIF metadata may vary across builds, so capture and review each built image digest instead of assuming byte-for-byte reproducibility. Backend capability uses the existing Web sandbox backend/digest configuration, existing release-specific worker heartbeat, and accepted worker image ID verification.
