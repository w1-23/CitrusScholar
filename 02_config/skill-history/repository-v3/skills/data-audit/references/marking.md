# 原表标注副本

审查与导出分离。review.json 绑定实际输入 bytes 与源哈希，保存逐表信封和全部 findings。导出只读该快照；原路径后来变化时也不重读为新输入。新文件路径必须不存在。

默认零附表，保留所有原 sheet 的名称和顺序。单元格发现用红底、红细边框和批注；同格多发现按严重度/规则/位置稳定合并，批注最多 1500 字符和 10 行，完整发现保留哈希引用。列级只在表头批注，表级只在 A1 批注；两者不染整列/整表。coverage_only 不着色、不批注。合并单元格只有锚点位于已审区域时标注。

同一源文件只生成一份合并标注工作簿，即使审查了多个区域或工作表；合并工作簿按 fileName/fileId + SHA-256 绑定来源，旧目录记录仍兼容。行级发现只覆盖该已审区域的真实列和行，不回退到全表宽度，也不跨表标注。普通 finding/evidence 坐标在触碰单元格前校验 sheet、原行列上界，不允许通过 ws[row] 扩表。输出重开后比较原数据区的坐标、值、类型、number_format 与合并范围，发现漂移则拒绝结果。

只有 --explain-visible 才在原 max_column+2 创建“审查解释（自动生成，非数据）”，中间空一列，按原行对齐并记录范围。问题清单、概览、规则附表分别用 --issue-list、--overview、--rules。问题清单保留序号/工作表/区域/单元格/行/列/列索引/问题类型/严重程度/原值/检测规则/说明/建议核查动作/结果层/计算定位证据。没有附表时不会留下指向不存在 sheet 的引用。

XLSX/XLSM 输出保留原数据语义；CSV 等来源生成新工作簿时明确为转换，长整数和公式样式文本保持文本。含 VBA 的 .xlsm 不能安全发布为 XLSX，应改交 HTML/JSON 或保留原宏格式的明确路径。文件中的签名、绘图或第三方扩展不属于原数据区保证，应在交付前按具体文件检查。立即发布和按 review_id 延迟导出必须共用同一渲染器，延迟路径只读记录且校验原 SHA-256。
