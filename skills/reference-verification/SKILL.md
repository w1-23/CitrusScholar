# 文献核验：身份对齐即可结束

## 默认目标
核实“这条引文对应哪一篇真实文献”。最低需要核对题名及能区分身份的作者、年份/版本或 DOI 等标识。页码格式、在线年份与卷期年份的差异可以记为备注，不为消除非关键格式差异无限查询。

## 批量策略
将用户原始条目作为一个批次处理，保留每条编号和原文。优先读取同一审计已存结果并复用去重查询。让宿主的批量服务执行有界并发，不用主模型逐条派发多个工具；具体调用参数以实际工具 schema 为准。

有 DOI 等精确标识时，使用已授权登记信息或权威落地页，并确认标识与题名身份一致。无标识时，使用已部署的网页 Search，以原题名加必要作者/年份定位。结果不足或冲突时，仅对该条采用有界补查。不要因“有一个 DOI 可以解析”就确认用户题名正确。

匹配到足够的身份依据立即结束该条。只有搜索结果未给出必要元数据时才定向读取书目落地页；默认不抓论文正文或 PDF。用户明确要求逐字段精校或论点核验时，再扩展相应范围。

## 结果
每条输出：已匹配、存在身份冲突、尚未确认；附对应标识/来源及一句必要说明。未查到、超时、无 DOI 不等于文献不存在或造假。不得生成 DOI。

批次处理结束可以包含尚未确认的条目；不要为了全部变成“已匹配”持续查询。报告“已处理多少条”和“确认多少条”两个不同数字。

沿用实际返回的 audit_id 读结果或导出，不重建库存，不使用过期 start_index 续跑说明。默认聊天给一张短表；只有用户要求才导出。完整证据留在结果存储中，主模型不必读回每个原始请求回执。

## 权限
检索通过宿主已授权网络服务。不要将平台密钥、其他账号资料或私有全文交给 Code。Code 可用于解析、去重和比较，不因此获得额外联网权限。
